# Работа в этом репозитории

Telegram-бот с расписанием соцфака МГУ и парсер к нему. Python 3.10+,
aiogram 3, SQLite, без внешних сервисов.

**Перед любой правкой парсера прочитай [docs/SITE.md](docs/SITE.md).**
Сайт-источник написан в нулевых, лежит несколько раз в неделю и заполняется
вручную. Почти каждое странное место в коде — ответ на конкретную странность
сайта, и она там описана с доказательствами. Правка «очевидного костыля» без
этого файла с большой вероятностью сломает то, что работает.

## Команды

```bash
python run_bot.py                       # бот, поллинг
python run_parser.py socio              # расписание групп, ~107 запросов, 2 мин
python run_parser.py subgroups          # языковые потоки, ~350 запросов, после socio
python run_parser.py teachers           # преподаватели с кафедр, ~586 запросов
python run_parser.py students           # студенты, ~3350 запросов, 40 мин
python run_parser.py students --resume  # продолжить прерванный прогон
python run_parser.py --test файл.html   # разбор сохранённой страницы, без сети

python -m unittest discover -s tests -t .   # тесты, сеть не нужна

python scripts/wait_for_site.py --check-only     # жив ли сайт
python scripts/scan_subgroups.py                 # у каких групп есть потоки
python scripts/measure_teachers.py --report-only # покрытие, без сети
python scripts/purge_old.py                      # смена семестра, сухой прогон
```

Виртуального окружения в репозитории нет — зависимости ставятся в системный
Python (`pip install -r requirements.txt`). На сервере `.venv` заводится,
это описано в [docs/DEPLOY.md](docs/DEPLOY.md).

## Правила

**1. Не ходи в живой сайт без необходимости.** Полный проход по студентам —
три с половиной тысячи запросов к чужому серверу, который и без нас еле
стоит. Для проверок есть `tests/fake_site.py` (мини-копия на localhost)
и `run_parser.py --test` на сохранённой странице. Живой прогон запускает
владелец репозитория, а не ты «чтобы посмотреть».

**2. Тесты не ходят в сеть.** Это не пожелание, а условие: тесты должны
проходить при лежащем сайте. Любая новая находка на живом сайте становится
тестом в `tests/test_parser_resilience.py` с разметкой, снятой с реальной
страницы.

**3. Молчаливая потеря данных запрещена.** Если парсер чего-то не получил
или не понял, это обязано попасть в `parse_log` и в вывод. 106 занятий
терялись каждый прогон ровно потому, что заметить их было нечем. Добавляешь
ветку, которая что-то пропускает, — добавляй счётчик.

**4. Считай покрытие от достижимого.** У МФК и физкультуры преподавателя
нет на самом сайте — это 904 занятия из 5724. «82% от всех» и «99.5% от
достижимого» описывают одно и то же состояние.

**5. Не переиспользуй HTTP-сессию между режимами.** Режим сайта (`группы` /
`mnu=75` / `mnu=56`) хранится в сессии, и после входа в студенческий режим
URL группового расписания отдаёт пустоту. Каждый `run_*` создаёт свой
`SocioParser` — так и должно оставаться.

**6. Не удаляй данные без резервной копии.** `scripts/purge_old.py` делает
её сам через `sqlite3 .backup`; файловое `cp` при включённом WAL может
потерять последние транзакции.

**7. Записывай изменения.** Заметное изменение поведения идёт в
`CHANGELOG.md` — с причиной, а не только с описанием. Находка про сайт идёт
в `docs/SITE.md`, нерешённое — в `docs/TODO.md`. Эти файлы и есть передача
контекста следующему, кто откроет репозиторий.

**8. Комментарии, докстринги и сообщения коммитов — по-русски.** Комментарий
объясняет *почему*, а не *что*: «сайт кладёт неэкранированные кавычки»
полезно, «экранируем кавычки» — нет.

## Перед коммитом

```bash
python -m unittest discover -s tests -t .    # 108 тестов, ~6 секунд, без сети
python -m compileall -q bot core parsers scripts tests *.py
git status --short          # .env и data/ не должны попадать в индекс
```

Тестам бота нужен установленный `aiogram` — он и так в `requirements.txt`.
Тесты работают на временных базах и боевую `data/schedule.db` не трогают;
если добавляешь тест, который лезет в базу, подменяй `core.database.DB_PATH`,
как это сделано в `tests/test_bot_routing.py`.

`.env` и `data/` в `.gitignore`. В `.env` лежит боевой токен бота —
не выводить его в лог, не вставлять в сообщения, не коммитить.

## Чего не делать

- **Не «чинить» время МФК по средам.** `PAIR_TIMES_WED_MFK` смотрит на день
  недели и не проверяет предмет — это факультетский регламент, а не костыль.
  Подробности в `docs/SITE.md` §8.
- **Не считать время окна по таблице пар.** `format_gap` берёт конец
  предыдущего занятия и начало следующего из самих данных именно потому,
  что по средам МФК идёт по своему расписанию звонков. Табличное время
  показало бы окно не там, где оно есть.
- **Не гнаться за 100% преподавателей.** См. правило 4.
- **Не сливать три прохода парсера в один.** Они разделены не случайно:
  у данных разная скорость жизни и разная цена сбора.
- **Никогда не запрашивать `?mnu=143`.** Выглядит как переключение
  в режим академических групп, а на деле это авторизованный модуль: отвечает
  «Не пройдена авторизация» и портит сессию — после него все страницы, включая
  расписания групп, отдают пустую заглушку. Анонимный режим групп — состояние
  свежей сессии по умолчанию, в него не заходят, в нём оказываются.
- **Не убирать `required=True`** с главной и входов в режимы. Без этого
  лежащий сайт даёт «успешный» прогон с пустой базой.
- **Не менять `MIN_LESSONS_PER_GROUP` на факультетский порог.** Именно
  из-за факультетского семь пустых групп проходили как «всё ок».

## Если прогон упал

`FetchError` на главной означает, что сайт лежит, а не что код сломан.
Проверить: `python scripts/wait_for_site.py --check-only`. Оборванный прогон
пишет в `parse_log` статус `partial` и сохраняет всё, что успел, — данные
не потеряны, прогон можно повторить.

Резкий рост «нераспознанных блоков» в `parse_log` означает, что сайт
изменили. Открыть страницу в браузере, сравнить с `docs/SITE.md` §3,
поправить разбор, добавить тест.
