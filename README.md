# MSU Schedule

Сервис расписания для студентов МГУ — автоматический сбор, Telegram-бот, веб-интерфейс.

Бот: [@msu_schedule_test_bot](https://t.me/msu_schedule_test_bot)

## Что делает

Парсеры собирают расписание с сайтов факультетов МГУ: групповые расписания, персональные расписания студентов, расписания преподавателей. Данные складываются в единую базу. Telegram-бот даёт студентам мгновенный доступ ко всему.

### Возможности бота

- Выбор группы кнопками (направление → курс → группа) или текстом
- Привязка по фамилии — студент находит себя, группа и предметы ставятся автоматически
- Расписание на сегодня / завтра / неделю с преподавателями
- Навигация по неделям (в пределах доступных данных)
- Фильтр предметов по выбору — автоматический при привязке или ручной
- Поиск расписания преподавателя по фамилии
- Корректное время пар, включая МФК-слоты по средам
- В выходные автоматически показывает следующую неделю
- Нормализация ввода (русская/английская раскладка, ввод без префикса)
- Аналитика пользователей и действий (`/stats`)
- Настраиваемая рекламная система через `.env`
- Алерты в Telegram при ошибках парсера

## Стек

Python 3.11, BeautifulSoup4, aiogram 3, SQLite (WAL), systemd на VPS.

## Парсинг

Три этапа, можно запускать по отдельности:

1. **Группы** (`python run_parser.py socio`) — ~107 запросов, 2 минуты. Расписания всех групп.
2. **Студенты** (`python run_parser.py students`) — ~3350 запросов, 30–40 минут. Персональные расписания, пофамильные списки, преподаватели из расписаний студентов.
3. **Преподаватели** (`python run_parser.py teachers`) — ~586 запросов, 5–10 минут. Дополняет преподавателей через кафедры + заполняет семинары от лекций.

Результат: 46 групп, 1101 студент, 69 преподавателей в занятиях.

### Устойчивость

Сайт факультета регулярно недоступен, поэтому прогон устроен так, чтобы
переживать обрывы:

- **Ретраи.** Каждый запрос повторяется до `PARSER_MAX_ATTEMPTS` раз с
  экспоненциальным бэкоффом. 404/403 не повторяются.
- **Сохранение по ходу.** Данные пишутся в базу после каждой группы (в
  режиме `teachers` — после каждого преподавателя). Обрыв на 900-м студенте
  больше не обнуляет предыдущих 899.
- **`students --resume`** пропускает группы, где предметы уже собраны, —
  прерванный прогон продолжается, а не начинается заново.
- **Статус `partial`** в `parse_log`, если прогон оборвался: данные есть,
  но неполные. `check_freshness.py` такой прогон свежим не считает.
- **Защита от затирания.** Если сайт отдал огрызок (меньше
  `SHRINK_GUARD_RATIO` от того, что лежит в базе за те же даты), запись
  не делается, а группа попадает в предупреждение.
- **Пороги на группу.** `MIN_LESSONS_PER_GROUP` ловит подозрительно пустые
  группы. Раньше порог был на факультет, и семь пустых магистерских групп
  проходили как «всё ок», потому что суммарно занятий хватало.
- **Счётчик нераспознанных блоков.** Блок расписания, не легший на
  регулярку, раньше исчезал молча — теперь считается и попадает в
  `parse_log` вместе с образцами.

### Замер кафедрального прохода

```
python scripts/measure_teachers.py --report-only   # текущий расклад, без сети
python scripts/measure_teachers.py                 # полный замер на копии базы
```

Отвечает на вопрос, сколько преподавателей даёт кафедральный проход сам по
себе, а не после студенческого. Если много — 3300 запросов студенческого
прохода можно убрать из пакетного цикла.

### Тесты

```
python -m unittest discover -s tests -t .
```

сайта на localhost с той же разметкой и умеет по команде падать.

## Схема данных

```
faculties          — факультеты
groups_            — группы (с привязкой к факультету, направлению, курсу)
lessons            — занятия (предмет, время, аудитория, преподаватель)
students           — пофамильные списки (ФИО, группа, site_id)
student_subjects   — предметы конкретного студента (для автофильтра)
subscriptions      — привязка Telegram → группа
user_subjects      — выбранные предметы пользователя (фильтр)
users              — Telegram-профили (аналитика)
activity_log       — действия пользователей (аналитика)
parse_log          — история парсинга (мониторинг)
```

## Технические заметки

Расписание соцфака: cp1251, PHP, навигация четырёхуровневая (отделение → направление → год набора → группа). Персональные расписания студентов — сессионная навигация (selst → pMns отдельными запросами).

По средам пары 4–5 — МФК-слоты с отдельным временем (15:10–16:40, 17:00–18:30), парсер определяет день недели и подставляет корректное время.

Преподаватели: 82% занятий с преподавателем. Цифра выглядит как незакрытый
хвост, но это не так. Из 908 занятий без преподавателя 888 — это МФК и
элективы по физкультуре, у которых преподавателя нет на самом сайте.
Реальных пробелов 20 из 5162, то есть **99,5% от достижимого**.

Разбивка «77% + 2% + 3%» — это предельные прибавки в том порядке, в котором
этапы запускали, а не способности методов: `update_lesson_teachers` пишет
только туда, где преподаватель пуст, поэтому кафедральному проходу досталось
23% остатка. Сколько он даёт с нуля — меряется через
`scripts/measure_teachers.py`.

ФГУ/юрфак — другая платформа (div-блоки, UTF-8, `/ttablestd/`). Отдельный адаптер, формат данных совместим.
