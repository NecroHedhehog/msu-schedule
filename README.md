# msu-schedule

Telegram-бот с расписанием социологического факультета МГУ и парсер, который
это расписание собирает.

Сайт факультета отдаёт расписание в виде таблиц образца нулевых, регулярно
лежит и заполняется вручную. Половина кода здесь существует именно поэтому:
парсер устроен так, чтобы переживать обрывы, замечать собственные потери и
не затирать хорошие данные плохими. Всё, что мы про этот сайт выяснили,
собрано в **[docs/SITE.md](docs/SITE.md)** — начинать стоит оттуда.

**Открыли репозиторий впервые?** Порядок чтения зависит от того, зачем:

| Задача | Читать |
|---|---|
| править код | [CLAUDE.md](CLAUDE.md) → [docs/SITE.md](docs/SITE.md) → [docs/TODO.md](docs/TODO.md) |
| поднять на сервере | [docs/DEPLOY.md](docs/DEPLOY.md) |
| понять, почему код такой | [CHANGELOG.md](CHANGELOG.md) — там причины, а не только описания |

## Что умеет бот

- расписание на сегодня, завтра и неделю, с навигацией по неделям
- окна между парами отмечены прямо в дне: `⌛ окно 1 пара · 12:10–14:00`
- выбор группы кнопками: отделение → направление → курс → группа
- поиск себя по фамилии и автоматическая отметка предметов по выбору
  (работает только после прохода `students`, см. «Парсинг»)
- ручной выбор предметов, если автофильтр не сработал
- выбор своего языкового потока (`/язык` или кнопка 🔤 Мой язык) — первый курс
- `❓ Помощь` — короткий гайд с разделами: предметы по выбору, языки, поиск, пустой день
- поиск расписания преподавателя по фамилии
- поиск группы текстом, с нормализацией раскладки (`c101` → `с101`)
- `💬 Связь` — свободный блок под контакт или объявление, настраивается в `.env`
- `/stats` для администратора: пользователи, активность, популярные группы
- алерты администратору в Telegram: сбои парсера, устаревшие данные

Клавиатура собирается под человека: кнопка `🔤 Мой язык` появляется только
у групп с языковыми потоками — это девять групп из сорока девяти.

```
📅 Сегодня   │ 📆 Завтра    │ 🗓 Неделя      расписание
📋 Предметы  │ 🔤 Мой язык  │ ❓ Помощь      что настраивается под себя
👨‍🏫 Преподаватель │ 👥 Сменить группу       поиск
💬 Связь                                    если задан в .env
```

День выглядит так:

```
📅 Четверг, 10 сентября
  📙 1 (09:00–10:30) СФ 317 [Сем]
     Подвойский Д.Г.
  📗 2 (10:40–12:10) СФ 522 [Лк]
  ⌛ окно 1 пара · 12:10–14:00
  📙 4 (14:00–15:30) ЗСххв 406 [Сем]
  ─────────
  🔤 Ваш язык
  · Английский язык
     3 (12:20–13:50) 405 Рассошенко Ж.В.  [1]
```

## Быстрый старт

```bash
git clone https://github.com/NecroHedhehog/msu-schedule.git
cd msu-schedule
pip install -r requirements.txt

cp .env.example .env            # и вписать BOT_TOKEN от @BotFather
python run_parser.py socio      # расписание групп, ~2 минуты
python run_parser.py subgroups  # языковые потоки, ~4 минуты
python run_bot.py
```

Windows PowerShell — то же самое, отличается только копирование файла:

```powershell
git clone https://github.com/NecroHedhehog/msu-schedule.git
cd msu-schedule
pip install -r requirements.txt

copy .env.example .env
notepad .env                    # вписать BOT_TOKEN
python run_parser.py socio
python run_parser.py subgroups
python run_bot.py
```

Требуется Python 3.10+. Виртуальное окружение не обязательно, но на сервере
уместно — там оно заведено в [docs/DEPLOY.md](docs/DEPLOY.md).

**Порядок проходов важен.** `subgroups` сохраняет только те занятия, которых
у группы ещё нет, поэтому идёт после `socio`. Имён преподавателей не будет,
пока не пройдёт `teachers`: на страницах групп их нет вовсе. Поиск по фамилии
не заработает, пока не пройдёт `students`.

Разворачивание на сервере — **[docs/DEPLOY.md](docs/DEPLOY.md)**.

## Парсинг

Три прохода, запускаются независимо. Преподавателя на страницах групп нет
вовсе — он появляется только в персональных расписаниях и на страницах
кафедр, поэтому проходов и три.

| Команда | Запросов | Время | Что даёт |
|---|---|---|---|
| `run_parser.py socio` | ~107 | 2 мин | занятия: предмет, время, аудитория, тип |
| `run_parser.py subgroups` | ~350 | 3–5 мин | языковые потоки первого курса |
| `run_parser.py teachers` | ~586 | 5–10 мин | преподаватели через кафедры, 64% покрытия |
| `run_parser.py students` | ~3350 | 30–40 мин | пофамильные списки, предметы студентов, преподаватели |
| `run_parser.py` без аргументов | ~4000 | ~40 мин | всё подряд |

Дополнительно: `students --resume` продолжает прерванный прогон,
`students --filter=с4` ограничивает выборку группами по маске кода,
`--test файл.html` разбирает сохранённую страницу без сети.

### Языковые потоки

Первый курс — и бакалавры, и магистры — учит разные языки: французский,
немецкий, английский у трёх преподавателей. Одним занятием на всю группу
это не показать, поэтому сайт режет группу на подгруппы и заводит каждую
отдельной сущностью. **В групповом расписании таких занятий нет вовсе.**

`run_parser.py subgroups` собирает их (~350 запросов) и кладёт в `lessons`
с непустой колонкой `subgroup`. Бот показывает их отдельным блоком «не у всех»
под расписанием дня, сгруппированным по языку.

Человек выбирает свой поток командой **`/язык`** или кнопкой **🔤 Мой язык**
(она появляется в клавиатуре только у групп с потоками — это девять групп
из сорока девяти). Сначала язык, потом конкретный поток: один преподаватель
нередко ведёт два, поэтому в списке показано ещё и время занятий.
В расписании остаётся одна строка вместо восьми.

Выбор хранится **смыслом**, а не номером потока:

| Признак | Живёт |
|---|---|
| номер потока `с101-3` | до конца семестра — коды групп пересобираются |
| преподаватель | годами |
| язык | практически вечно |

Хранятся все три, и каждый уровень при устаревании отбрасывается по
отдельности: исчез номер потока — остаётся преподаватель, сменился
преподаватель — остаётся язык, исчез язык — фильтр выключается совсем
и снова показываются все потоки.
Сломаться это не может, в худшем случае деградирует до поведения по умолчанию.

Потоки для иностранных студентов не собираются вовсе — `SKIP_SUBGROUP_SUBJECTS`
в `.env`, правило по названию предмета, а не по коду группы.

Запускать **после** `socio`: сохраняются только занятия, которых у группы
нет, а для этого расписание группы должно уже лежать в базе.

### Устойчивость

Сайт недоступен по несколько раз в неделю, и прогон это переживает:

- **Ретраи.** Каждый запрос повторяется до `PARSER_MAX_ATTEMPTS` раз
  с экспоненциальным бэкоффом и джиттером. 404 и 403 не повторяются.
- **Критичные страницы.** Главная и входы в режимы (`mnu=75`, `mnu=56`)
  помечены `required`: если они не открылись, прогон падает с `FetchError`,
  а не собирает пустоту, отрапортовав «ок».
- **Сохранение по ходу.** Данные пишутся после каждой группы (в режиме
  `teachers` — после каждого преподавателя). Обрыв на 900-м студенте
  из 1101 больше не обнуляет предыдущих 899.
- **Статус `partial`.** Оборванный прогон пишется в `parse_log` отдельным
  статусом: данные есть, но неполные. `check_freshness.py` такой прогон
  свежим не считает.
- **Защита от затирания.** Если пришло меньше `SHRINK_GUARD_RATIO` от того,
  что уже лежит в базе за те же даты, запись не делается — группа уходит
  в предупреждение вместо того, чтобы потерять расписание.
- **Пороги на группу.** `MIN_LESSONS_PER_GROUP` ловит подозрительно пустые
  группы поимённо. Факультетский порог этого не ловил: суммарно занятий
  хватало, и семь пустых групп проходили как «всё ок».
- **Счётчик нераспознанных блоков.** Блок расписания, не легший на регулярку,
  раньше исчезал молча. Теперь считается и попадает в `parse_log` вместе
  с образцами — именно так нашлись 106 занятий, терявшихся каждый прогон
  из-за неэкранированных кавычек в разметке.

## Обслуживание

```bash
# жив ли сайт (код возврата 0/1, годится для крона)
python scripts/wait_for_site.py --check-only

# дождаться сайта и сразу собрать расписание
python scripts/wait_for_site.py --then socio

# смена семестра: убрать прошлый, коды групп переиспользуются
python scripts/purge_old.py                          # сухой прогон
python scripts/purge_old.py --before 2026-09-01 --students --yes

# у каких групп есть языковые потоки (~47 запросов, ничего не меняет)
python scripts/scan_subgroups.py

# сколько преподавателей даёт каждый источник
python scripts/measure_teachers.py --report-only     # без сети
python scripts/measure_teachers.py                   # полный замер на копии базы
```

## Схема данных

```
faculties          факультеты
groups_            группы (факультет, направление, год набора, site_id)
lessons            занятия (дата, пара, время, предмет, аудитория, тип, преподаватель)
                   subgroup — пусто у обычных, метка потока у языковых
students           пофамильные списки (ФИО, группа, site_id)
student_subjects   предметы конкретного студента — для автофильтра
subscriptions      привязка Telegram → группа
user_subjects      предметы, выбранные пользователем вручную
user_streams       выбранный языковой поток (предмет + преподаватель + поток)
users              Telegram-профили и привязка к студенту (аналитика)
activity_log       действия пользователей (аналитика)
parse_log          история прогонов: статус, счётчики, что пошло не так
```

## Тесты

```bash
python -m unittest discover -s tests -t .
```

108 тестов, около шести секунд, ни один не ходит в сеть и не трогает боевую базу.

`tests/fake_site.py` поднимает мини-копию сайта на localhost с той же
разметкой — включая поломанную — и умеет по команде падать. Покрыты ретраи,
отказ от повторов на 404, `FetchError` на критичной странице, защита от
затирания, счётчик нераспознанных блоков, починка кавычек в `title`
и главное: что после каждой группы данные видны из **отдельного** соединения
к базе, то есть переживут смерть процесса.

`tests/test_formatting_gaps.py` отдельно закрывает окна между парами —
включая случай, когда окно закрыто выбранным языковым потоком.

`tests/test_bot_routing.py` гоняет настоящие апдейты через `Dispatcher`
с подменённым транспортом вместо Telegram — проверяется, что нажатие кнопки
и следующий за ним текст попадают в нужный обработчик. Именно эта проверка
дважды находила дыры, которых юнит-тесты не видели.

Любая новая находка на живом сайте должна становиться тестом здесь же.

### Что лежит в базе на 09.09.2026

Снимок для того, кто разворачивает проект и хочет понять, что нормально,
а что повод разбираться:

| | |
|---|---|
| групп в навигации сайта | 49 |
| из них с расписанием | 43 — у шести его на сайте пока нет |
| занятий | 6768 за 01.09–30.10 |
| из них языковых потоков | 1044 у 9 групп (первый курс) |
| студентов | **0** — проход `students` не гоняли |
| размер базы | 1.8 МБ |

**Два следствия непройденного `students`**, и оба заметны пользователю:

1. Не работают «🔍 Найти себя по фамилии» и автоотметка предметов по выбору.
2. Преподаватель стоит у 3080 занятий из 4820 достижимых — **64%**.
   Кафедральный проход `teachers` больше и не даёт; недостающее лежит
   в персональных расписаниях студентов, то есть приезжает вместе
   с проходом `students`. Вместе получается 99.5% — так было весной.

«Достижимое» — это все занятия минус 904 занятия МФК и физкультуры,
у которых преподавателя нет на самом сайте. Почему считать надо именно так —
правило 4 в [CLAUDE.md](CLAUDE.md) и [docs/measurements-2026-09.md](docs/measurements-2026-09.md).

Всё это — первый пункт в [docs/TODO.md](docs/TODO.md).

## Настройки

Все в `.env`, шаблон с пояснениями — [.env.example](.env.example).
Обязательны только `BOT_TOKEN` и `ADMIN_CHAT_ID`; остальное имеет разумные
значения по умолчанию.

Стоит знать про два:

- `SKIP_SUBGROUP_SUBJECTS` — какие языковые потоки не собирать. По умолчанию
  отсеиваются занятия для иностранных студентов: правило по названию предмета,
  а не по коду группы, потому что коды пересобираются каждый семестр.
- `AD_TEASER` / `AD_FULL_TEXT` / `AD_BUTTON_LABEL` — свободный блок: подпись
  под расписанием и нижняя кнопка с произвольным текстом. Название
  историческое; на боевом стенде там стоит контакт для сообщений об ошибках.
  Пустой `AD_FULL_TEXT` убирает кнопку совсем.

`.env` в git не попадает намеренно — в нём боевой токен. При переносе
на сервер он копируется руками, см. [DEPLOY.md §2.1](docs/DEPLOY.md).
