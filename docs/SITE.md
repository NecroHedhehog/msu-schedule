# Сайт, с которым мы имеем дело

`http://cacs.socio.msu.ru` — «Автоматизированная система управления учебным
процессом социологического факультета МГУ». PHP, кодировка cp1251, вёрстка
таблицами, только `http` (https не отвечает вовсе). Написана в нулевых и с тех
пор, судя по разметке, не переписывалась. Расписание туда выкладывают вручную
и неаккуратно.

Этот файл — не жалоба, а справочник: всё, что мы про этот сайт выяснили
опытным путём, с доказательствами и с выводами для кода. Каждый пункт проверен
на живом сайте, даты проверок указаны.

**Главное правило: сайт — источник истины, но не источник надёжности.**
Ни один его ответ нельзя считать полным, корректным или воспроизводимым.
Всё, что парсер получает, должно проверяться и уметь не сохраняться.

## 1. Доступность

Сайт регулярно недоступен, без предупреждений и без закономерности. Это не
отказ сервера, а обрыв на сетевом уровне: `ConnectionError`, соединение не
устанавливается вовсе.

Наблюдение 08.09.2026, проверка раз в пять минут:

```
10:59  ConnectionError
11:04  ConnectionError
11:09  ConnectionError
11:15  ConnectionError
11:21  OK, 73808 байт      ← поднялся через 22 минуты
```

При этом соседний `www.socio.msu.ru` работал всё это время. Проблема
именно в хосте расписания.

**Следствия для кода:**

- каждый запрос повторяется с бэкоффом (`PARSER_MAX_ATTEMPTS`, `download()`)
- прогон сохраняет по мере продвижения, а не одним куском в конце
- прогон, который не доехал, пишет в `parse_log` статус `partial`, а не `ok`
- перед долгим прогоном имеет смысл дождаться сайта: `scripts/wait_for_site.py`
- живым сайт считается не по коду 200, а по наличию ссылок `?f=N` на главной:
  заглушка провайдера тоже отвечает двумястами

## 2. Навигация: четыре уровня и липкий режим

Расписание группы достаётся так:

```
/index.php                    главная, ссылки ?f=N   — отделения
/index.php?f=1                отделение, ссылки ?sp=N — направления
/index.php?sp=1               направление, <select name="yr"> — годы набора
/index.php?yr=45              год набора, ссылки ?gr=N — группы
/index.php?gr=473&pMns=9.2026 расписание группы на месяц
```

Месяц задаётся как `pMns=M.YYYY` (без ведущего нуля: `9.2026`, не `09.2026`).

Кроме группового есть ещё два режима, и **режим липкий — он живёт в сессии**:

| Режим | Вход | Дальше |
|---|---|---|
| Группы | по умолчанию | `?gr=N&pMns=` |
| Студент | `?mnu=75` | `?gr=N` → список студентов → `?selst=N` → `?pMns=` |
| Преподаватель | `?mnu=56` | `?k=N` (кафедра) → `?prr=N` → `?pMns=` |

**Проверено 08.09.2026:** после захода на `?mnu=75` запрос
`?gr=367&pMns=9.2026` возвращает страницу **без единого занятия**. Тот же URL
в свежей сессии отдаёт 77 блоков. То есть URL не самодостаточен: результат
зависит от того, что запрашивали до этого.

**Следствия для кода:**

- каждый режим — свой `requests.Session`. В `run_parser.py` так и есть: каждый
  `run_*` создаёт свой `SocioParser`. Не «оптимизируйте» это в одну сессию.
- `?mnu=75` и `?mnu=56` помечены `required=True`: если вход в режим не удался,
  прогон обязан упасть, а не собирать пустоту в режиме групп
- порядок запросов внутри режима менять нельзя: `selst` выбирает студента
  в сессии, `pMns` потом отдаёт расписание выбранного

## 3. Разметка занятия

```html
<div id="LESS" title="Лекция по 'Методология и методика социологического исследования'">
  <font color="#004000"><b>ММСИ</b></font><br>
  <b>511</b>[<font color="#8D2183">Лк</font>]<br>
</div>
```

- `id="LESS"` — именно `id`, и он повторяется на странице десятки раз.
  HTML невалиден, но парсеры это переживают. Селектор по `id` тут работает
  как селектор по классу.
- `title` — единственное место, где предмет написан полностью:
  `Тип по 'Название'`. В самом блоке только аббревиатура.
- аббревиатура — `<b>` внутри `<font color="#004000">`
- аудитория — следующий `<b>`, вне зелёного `font`
- тип занятия — `<font color="#8D2183">` внутри квадратных скобок
- преподаватель — текст **после** `]`, и его там может не быть (см. §5)
- номер пары в разметке отсутствует: пара определяется позицией ячейки
  `<td class="TmTblC">` внутри таблицы дня (см. §7)

### 3.1. Неэкранированные кавычки в title

Если в названии предмета есть кавычки, сайт кладёт их в атрибут как есть:

```html
<div id="LESS" title="Лекция по 'Анализ статистической информации
     в программе "Статистический пакет для социальных наук"'">
```

Любой HTML-парсер — и BeautifulSoup, и сам Chrome — обрывает атрибут на первой
внутренней кавычке. Получается обрубок без закрывающей апострофы, регулярка
не срабатывает, занятие теряется.

**Масштаб:** 106 занятий за прогон, два предмета — «Анализ статистической
информации в программе "Статистический пакет для социальных наук"» и
«Профессиональные деформации в системе "Человек-человек"».

Чинится в `SocioParser._repair_lesson_titles`: внутренние кавычки экранируются
до разбора, настоящий конец атрибута определяется по `">`, а не по первой
кавычке. Починка сужена до `div` занятия — у `td` и `a` атрибут `title` не
последний, и той же меркой их ломать нельзя.

### 3.2. Хвост «Добавлено» у свежих занятий

Недавно добавленные занятия сайт помечает сам:

```html
<div id="LESS"style="..." title="Лекция по 'Социальное пространство современных
     городов' Добавлено 03.09.2026,14:20">
```

Два отличия: `style` приклеен к `id` **без пробела**, и в `title` появляется
хвост с датой и временем добавления. Регулярка `(.+?) по '(.+)'` это переживает
(она не якорится на конец), но помнить стоит.

Это, к слову, **готовая зацепка для уведомлений об изменениях** — сайт сам
говорит, что появилось недавно. Колонка `notify_changes` в `subscriptions`
уже заведена, фича не написана.

## 4. Кодировка

Страницы в `cp1251`, заголовок объявляет `windows-1251`. `requests` угадывает
неправильно, поэтому кодировка задаётся вручную:

```python
resp.encoding = 'cp1251'
```

При чтении через `fetch()` в браузере — `TextDecoder('windows-1251')` поверх
`arrayBuffer()`, иначе получите мусор вместо кириллицы.

## 6. Личные расписания личные не везде

На курсах без предметов по выбору расписание студента совпадает с расписанием
группы. Проверено 08.09.2026:

| Группа | Курс | В группе | Проверено | Наборы предметов |
|---|---|---|---|---|
| с101 | 1 | 36 | 5 | одинаковые, по 10 предметов |
| с301 | 3 | 19 | 5 | одинаковые, по 10 предметов |
| с401 | 4 | 19 | 4 | разные, 10–11 предметов |

Первый же студент первого курса даёт все 10 предметов группы, следующие четверо
не добавляют ничего. На четвёртом курсе наборы личные: у одной студентки
«Гендер, пол и семья», у другой на этом месте «Счастье и субъективное
благополучие». По весенним данным там нужно опросить в среднем 7 студентов
из 22, чтобы собрать все предметы группы.

**Следствие:** опрашивать всех подряд не нужно. Правило «идти по студентам,
пока появляются новые предметы, и останавливаться после нескольких пустых
подряд» само подстроится под курс.

## 6.1. В списке «студентов» лежат не только студенты

Проверено 08.09.2026. Список, который отдаёт `?gr=N` в режиме `mnu=75`,
содержит записи двух разных сортов, и внешне они неотличимы — одинаковые
строки `<tr onclick="...selst=N...">`:

| Запись | Что это |
|---|---|
| `21217: Авдохина С.Б.` | живой студент |
| `22881: мг51соврс-1` | **подгруппа**, а не человек |
| `22905: мг55кпсм-1` | подгруппа |
| `22811: ` *(пустая метка)* | ??? |

Подгруппы — это деление группы для языков и подобных занятий, которые
идут не всей группой. Обращаются к ним так же, как к студенту: `?selst=22881`.

**У части групп людей в списке нет вообще, только подгруппы:**

| Группа | Записей в списке | Из них людей | Занятий у группы |
|---|---|---|---|
| мг55кпсм (`gr=471`) | 3 | 0 | 69 |
| мг56сасид (`gr=472`) | 3 | 0 | **0** |
| мг61соврс (`gr=426`) | 1 | 0 (пустая метка) | 8 |
| мг51соврс (`gr=467`) | 25 | 24 + подгруппа | 70 |

Отсюда рабочая гипотеза: **ноль занятий у `мг56сасид` — это не «расписание
ещё не выложили», а «расписание лежит под подгруппами».** Проверить сравнением
расписания группы и её подгрупп не успели: сайт лёг посреди проверки.

### Что из этого следует

1. **Подгруппу нельзя записывать в `students`.** Иначе в боте по кнопке
   «найти себя по фамилии» человек увидит запись «мг51соврс-1» и сможет
   к ней привязаться. Отличать по метке: у подгруппы она имеет вид
   `<код группы>-<цифра>`, у человека — фамилия с инициалами.
2. **Расписание подгруппы — это расписание группы, а не персональное.**
   Собирать его надо в режиме групп и складывать к занятиям группы,
   а не в `student_subjects`.
3. **Пустая метка** (`22811`) — отдельный случай, назначение неизвестно.

### Порядок навигации важнее, чем кажется

Сайт хранит режим и позицию в сессии, и `?gr=N` работает только после
прохода по цепочке. Свежая сессия открывается в режиме групп, поэтому
парсер это не замечает — но стоит запросить `?mnu=` другого режима,
и групповые страницы начинают отдавать пустоту.

Режимов ровно три, ссылки на них есть на главной:

| Режим | Вход |
|---|---|
| Академ. группы | `?mnu=143` |
| Преподавателя | `?mnu=56` |
| Студента | `?mnu=75` |

`parse()` в `mnu=143` явно не заходит — полагается на то, что сессия свежая.
Это работает, потому что каждый `run_*` создаёт свой `SocioParser`, но лучше
заходить явно.

Сама система, судя по подвалу, — переделка чужого продукта 2007 года
(«©2007 Сумской Национальный Аграрный Университет»). Это многое объясняет.

## 7. Номер пары берётся из позиции, а не из данных

```python
for i, cell in enumerate(table.find_all('td', class_='TmTblC')):
    pair = i + 1
```

Пока сайт рисует ровно шесть ячеек на день, это верно — в базе честные 1…6

## 8. Время пар и среда

Обычная сетка:

```
1  09:00–10:30    4  14:00–15:30
2  10:40–12:10    5  15:40–17:10
3  12:20–13:50    6  17:20–18:50
```

**По средам пары 4 и 5 идут в другое время: 15:10–16:40 и 17:00–18:30.**
Это не эвристика и не костыль, а факультетский регламент: в среду ставятся
только первые три обычные пары, дальше слоты под межфакультетские курсы.
Данные подтверждают — все 515 весенних занятий на средах 4–5 парой были МФК,
без единого исключения.

Поэтому `PAIR_TIMES_WED_MFK` смотрит только на день недели и не проверяет
предмет. **Это правильно, не «чините».**

## 9. Группы: пустые, исчезающие, переиспользованные

### 9.1. Пустая группа — это нормально

На 08.09.2026 у `с107`, `пп202` и `мг56сасид` не было ни одного занятия
на сентябрь. Проверено на сайте: расписание им действительно ещё не выложили.
Парсер обязан такие группы показывать в предупреждении, но не считать ошибкой
и не падать.

Порог здесь — **на группу** (`MIN_LESSONS_PER_GROUP`), а не на факультет.
С факультетским порогом семь пустых групп проходили как «всё ок», потому что
суммарно занятий по факультету хватало.

### 9.2. Группы исчезают

Наборы выпускаются, и коды пропадают из навигации: `пп302`, `пп402`, `с208`
были весной и отсутствуют осенью. В базе они остаются навсегда, потому что
парсер их просто не встречает и ничего про них не сообщает.

На 08.09.2026 один подписчик бота сидел на `пп402` — группе, которой больше
нет. Он видит пустоту и не понимает почему.

**Не сделано:** колонка `last_seen` в `groups_`, которую парсер проставляет
на каждом обходе. Тогда бот сможет отличить «расписание ещё не выложили»
от «такой группы больше нет» и сказать человеку правду.

### 9.3. Коды переиспользуются между наборами

Самое неприятное. Весенний `с101` — это осенний `с201`: набор перешёл на
следующий курс, а код освободился для новых первокурсников.

`get_or_create_group` матчит группу по паре (факультет, код), поэтому после
первого же прогона нового семестра под кодом `с101` лежат и сентябрьские
занятия нынешних первокурсников, и мартовские занятия совсем других людей.
На 08.09.2026 таких групп было 39 из 46.

Пока лечится вручную при смене семестра — `scripts/purge_old.py`.
Правильное решение — хранить год набора (он есть на сайте: `yr=45`, `yr=42`…)
и матчить по паре код+набор.

## 10. Что из этого следует для кода

Свод правил, каждое выведено из пунктов выше:

1. **Ни один ответ не считается полным.** Пороги на группу, защита от
   затирания огрызком, счётчик нераспознанных блоков — всё это не паранойя,
   а минимум.
2. **Молчаливая потеря запрещена.** Если парсер чего-то не понял или не
   получил, это обязано попасть в `parse_log` и в вывод. История с 106
   потерянными занятиями держалась ровно на том, что терять было нечем
   заметить.
3. **Сохранять по ходу.** Обрыв на середине не должен обнулять собранное.
4. **Считать покрытие от достижимого**, а не от всех занятий.
5. **Режим сессии не переиспользовать** между `socio` / `students` / `teachers`.
6. **Тесты не должны ходить в сеть.** `tests/fake_site.py` поднимает
   мини-копию сайта на localhost с той же разметкой, включая поломанную.
   Любая новая находка на живом сайте должна становиться тестом там же.
7. **Проверять гипотезы на живой разметке, а не на своих ожиданиях.**
   Половина сегодняшних находок — это места, где код делал разумное
   предположение, а сайт вёл себя иначе.

## 11. Как посмотреть самому

Из браузера, на любой странице сайта (нужна та же сессия для режимов):

```js
const dec = new TextDecoder('windows-1251');
const get = async u => dec.decode(await (await fetch(u, {cache:'no-store'})).arrayBuffer());

// расписание группы на месяц
const html = await get('/index.php?gr=367&pMns=9.2026');

// то же в режиме студента, с преподавателями
await get('/index.php?mnu=75');
const roster = await get('/index.php?gr=367');
const id = /selst=(\d+)/.exec(roster)[1];
await get(`/index.php?selst=${id}`);
const personal = await get('/index.php?pMns=9.2026');
```

Из проекта:

```
python scripts/wait_for_site.py --check-only    # жив ли сайт
python run_parser.py --test путь/к/файлу.html   # разбор сохранённой страницы
```
